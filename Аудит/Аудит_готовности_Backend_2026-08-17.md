## 2. Inbound `/exchange` — рассинхрон со спекой и 1С

`ExchangeController`: берёт `event` + `payload`, отдаёт handler, **без подписи и allowlist**.

`WebhookHandlerFactory` обрабатывает только:

- `sync.products`, `sync.product-attributes`, `sync.product-types`, `sync.product-type-characteristics`
- `sync.stocks`, `sync.prices`, `sync.categories`, `sync.counterparties`
- `sync.documents`

**Нет:** статусы заказа, состав ТЧ (`sync.order-items` — есть задание аналитики, кода нет). Неизвестный event → **400**.

| Риск | Почему это ошибка |
|------|-------------------|
| Любой POST перезапишет каталог/документы | Нет HMAC |
| 1С шлёт статус по будущему event | 400 / тишина; ЛК не обновится |
| 1С шлёт состав заказа | То же; строки на платформе устареют |

## 3. Претензии — баги (не только «не доделано»)

`CreateClaimRequest`:

- `order_id` → `required|exists:orders,id` — **любой заказ в БД**, не «свой контрагент».
- `items.*` → `exists:order_items,id` — **любая строка любого заказа**.

`ClaimService`:

```text
OrderItem::query()->find($orderItemId)->order_id == $claim->order_id
```

| ID | Ошибка |
|----|--------|
| **B7** | Залогиненный пользователь может создать претензию на чужой `order_id` |
| **B2** | `find()` → `null` → обращение к `->order_id` (гонка / рассинхрон id) |
| **==** | Нестрогое сравнение id |

Фронт уже показывает claims UI: дыра **эксплуатируема с демо**, не «потом, когда появится страница».

## 4. Заказ → 1С

Контракт (закрыт 08-07, без регресса в дереве `ad55296`):

- Outbound: `externalGuid`, `productGuid` + `productCharacteristicGuid`, цены string, ответ `orderNumber` → `order.number`.
- Вход с фронта: если FE шлёт `'null'` в date/comment — бэк **пропустит как строки** (нет нормализации). Это рассинхрон FE↔BE↔1С: платформа не защищает ERP от мусора.
