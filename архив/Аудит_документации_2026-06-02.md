## 1. Краткое видение проекта

Palizh — **B2B-платформа** (витрина + ЛК) для клиентов с контрагентом и договором в **1С ERP 2.5.22**. Ядро MVP: каталог с персональными ценами после входа, **корзина с расчётом на backend (вариант A)** — смешанная строка (`amount` за штуку, `amountPerBox` за коробку), оформление заказа, счёт из 1С, **6 статусов** в ЛК, документы, доставка/самовывоз, email-уведомления, претензии, онбординг, админка.

Интеграция каталога: **`POST /exchange`** (1С → платформа), заказы — **`POST /post_orders`**, документы — **`GET /get_documents`**. Канон публичного API стенда — **`public-http-openapi.yaml`** (GitLab `docs/`). Поиск по каталогу — **на платформе** (`GET /search/products`), без Ensi/Bitrix. Адреса доставки — **DaData** на фронте, `deliveryAddress` + `deliveryAddressFiasId`.

**Сильные стороны документации (после недавних правок):** ЧТЗ 01 §4.2.4 (цены корзины), ЧТЗ 06 §4.2.3–4.2.4, ЧТЗ 11 (поиск), `Принятые_решения_API_интеграция_1С.md` §4, `openapi_mvp_cart_checkout_orders.md` §5.3, закрытие **№57**.

**Главные разрывы:** устаревшие формулировки «без расчёта на платформе», **отставание канона `public-http-openapi.yaml`** (поиск, поля корзины), **хвосты Ensi** в матрице/плане бэкенда, рассинхрон вторичных артефактов (матрица статусов, маппинг 1С, Инфарх).
