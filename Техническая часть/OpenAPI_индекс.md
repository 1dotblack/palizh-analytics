# OpenAPI Palizh: какие файлы для чего

Контракты **разделены по назначению** (клиент ↔ бэкенд и server-to-server с 1С). Монолитный `openapi_mvp.yaml` **снят**; копия последнего объединённого варианта — в `архив/openapi_mvp_monolith_2026-04-17.yaml`.

| Файл | Назначение | Кто потребляет |
| ---- | ---------- | -------------- |
| [`openapi_client_mvp.yaml`](openapi_client_mvp.yaml) | **Витрина и ЛК:** онбординг, `auth`, профиль, каталог, корзина, оформление, заказы, документы по заказу. JSON + **JWT** — **браузер, мобильное приложение** (через бэкенд). | Фронтенд, мобильная команда, контрактные тесты публичного API |
| [`openapi_1c_inbound_mvp.yaml`](openapi_1c_inbound_mvp.yaml) | **Входящие 1С → платформа:** **`POST /exchange`** (`event` + `payload`). **HMAC** + allowlist IP. **Без UI.** См. [`Принятые_решения_API_интеграция_1С.md`](Принятые_решения_API_интеграция_1С.md). | Разработка 1С, бэкенд приёма интеграции |
| [`1c-http-openapi.yaml`](1c-http-openapi.yaml) | **Исходящие вызовы платформа → HTTP-сервисы 1С** (заказ, выдача файла документа и т.д. по согласованию). **Basic** и сеть — на стороне заказчика. | Бэкенд платформы, разработка 1С (публикации) |
| [`openapi_mvp_merged.yaml`](openapi_mvp_merged.yaml) | **Объединение** клиент + 1С inbound (генерация скриптом). Для Redoc/Swagger UI, линтеров, которым удобен **один** YAML. **Не править вручную.** | Демо, CI, просмотр «всё в одном» |
| [`openapi_mvp_полный_черновик.yaml`](openapi_mvp_полный_черновик.yaml) | Post-MVP расширения (претензии, админка, обучение и т.д.). | Планирование |

**Скрипты** (каталог `Техническая часть/tools/`):

- `merge_openapi_mvp.rb` — пересобирает `openapi_mvp_merged.yaml` из `openapi_client_mvp.yaml` + `openapi_1c_inbound_mvp.yaml` (запускать после правок двух исходников).
- `split_openapi_client_and_1c.rb` — одноразовая нарезка; источник по умолчанию — архивный монолит, если снова понадобится регенерировать куски из старой одной спеки.

**Канон для изменений в MVP:** править **`openapi_client_mvp.yaml`** и/или **`openapi_1c_inbound_mvp.yaml`**, затем при необходимости `ruby tools/merge_openapi_mvp.rb`.
