## Контекст

Команда показала текущую реализацию фильтра оттенков и выбора цвета на **карточке сборника**. Параллельно в чате прозвучало, что сборники могут уйти из каталога. Нужно было зафиксировать бизнес-правила: что остаётся в витрине, как группировать обычные товары с разными цветами/фасовками и откуда брать признак группировки в 1С.

---

## Принятые решения

### 1. Сборники (~5%) — вне каталога

| Тема | Решение |
|------|---------|
| Витрина / листинг | **Сборников в каталоге нет** |
| Карточка сборника | **Не делаем** |
| Фильтр по цветам сборников | **Не показываем** |
| Новый заказ цвета «под клиента» (RAL и т.п.) | Форма **нестандартной заявки** → менеджер |
| Повтор того же цвета | Только из **истории заказов** ЛК |

**Обоснование (Андрей):** сборник — цвет **под конкретного клиента**, не массовый продукт.

### 2. Обычные товары (~95%) — цвета в каталоге остаются

- Цвет / hex — в **доп. реквизитах номенклатуры** (атрибуты `color` / `hex`), не как характеристики сборника.
- Фильтр «оттенки цветов» и работа с цветом на витрине **сохраняются**, но **перенастраиваются** с модели «характеристики сборника» на **цвет обычного товара**.
- Текущая реализация «только под сборники» — следствие того, что в обмен **сначала** пришли сгруппированные сборники; обычная номенклатура пришла позже и **не сгруппирована**.

### 3. Карточка: не один SKU с вариантами цвета, а группа по торговому предложению

| Утверждение | Смысл |
|-------------|--------|
| «8 лаков разных цветов» | Это **разные товары (SKU)** в 1С, не один товар с 8 характеристиками |
| Объединение на сайте | По реквизиту **наименования торгового предложения** (рабочее имя; уточнить код поля у Стаса / Натальи) |
| В карточке | Выбор **цвета** среди SKU одной группы; при выбранном цвете — варианты **фасовок** (0,2 кг / 5 л / 10 л и т.п.), как на текущем сайте |
| Фильтр оттенков | Ведёт к листингу SKU; открытие карточки — уже в контексте группы торгового предложения |

Пример UX (Наталья): фильтр «красные» → товар 325 → в карточке другие цвета той же группы → внизу фасовки для выбранного цвета.

---

## Что переделать на платформе (ориентир для команды)

1. **Убрать / не развивать** каталожный UX сборников (фильтр + swatches на КТ из характеристик сборника).
2. **Источник цвета для фильтра и плашек** — атрибуты обычной номенклатуры (`hex` / `color`).
3. **Группировка карточки** — по полю «наименование торгового предложения» (после того как 1С отдаст стабильный ключ в обмене).
4. В КТ: UI **цвет + фасовка** внутри группы; переход по цвету = смена SKU (другой `productGuid`), не характеристика одного продукта.
