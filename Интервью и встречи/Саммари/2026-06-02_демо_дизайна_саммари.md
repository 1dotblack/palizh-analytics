## Ключевые договорённости

### 1) Регистрация / активация

- **MVP (уточнено после демо):** заявка «Стать клиентом» **без пароля**; пароль задаётся по ссылке из письма **после активации в 1С** (не на этапе заявки).
- Срок жизни ссылки на **установку пароля** — **7 дней** (`EMAIL_ACCESS_GRANTED`, ЧТЗ 05 §4.3.2).
- На макетах демо 2026-06-02 обсуждался вариант «пароль при регистрации + verify email» — **не принят** для MVP.

### 2) Вход

- Обсуждён вариант явно подписывать поле как **email**, а не абстрактный «логин», чтобы не было путаницы у пользователей.
- Секция восстановления пароля подтверждена как стандартный поток.

### 3) Главная

- В hero убрали блок карточек товаров.
- Баннер остаётся промо-блоком с CTA; ссылка может вести как в акцию, так и в каталог (по настройке).
- Для desktop и mobile нужны отдельные баннерные версии (разные изображения/композиция).

### 4) Каталог / фильтры / 1С

- Для группировок и фильтрации подтверждена **гибкая модель атрибутов** (актуализация **2026-06-26**):
  - справочник — **`sync.product-attributes`**, значения на товаре — **`attributes[]`** в **`sync.products`**;
  - рабочий набор кодов MVP: `worktype`, `surface`, `special`, `compatibility`, `tintingMethod`, `density` (ЧТЗ 06 §4.2.0);
  - в UI отображаются **`label`** из справочника (например «Типы работ» для `worktype`).
- ~~Отдельные поля `applicationScope` / `workType` в шапке товара~~ — **устарело** (заменено на `attributes[]`).
- По категориям подтвердили использование родительских связей (`parent`).
- Принцип расширения: новые фильтровые свойства добавляются в 1С через **`sync.product-attributes`** и передаются в выгрузке без смены контракта API.

### 5) Mobile vs Desktop

- Табличный вид каталога оставляем только для desktop.
- На мобильных — карточки; табличный режим в mobile признан нецелесообразным.

## Обсуждение, требующее доработки (важно)

### A. Логика «коробка / штука»

Основной незакрытый вопрос встречи:
- как корректно показывать цену и количество при покупке кратно упаковке;
- что делать с товарами, у которых нет «коробки» (только штучная единица);
- нужно ли отдельное визуальное уведомление о некратности упаковке.

Общий вектор:
- не делать отдельные карточки «товар-коробка»;
- передавать упаковочные данные из 1С и решать логику на карточке/в корзине;
- доработать UX, чтобы пользователь понимал, когда количество некратно упаковке.

### B. Цветовые группы / оттенки

- Поиск оттенков и групп цветов в фильтрах согласован концептуально.
- Требуется окончательная техническая договорённость, как именно маппятся цвета/оттенки на данных из 1С.
